# Деплой на Render — живая ссылка на приложение

Сайт: **https://olymp-trainer.onrender.com**

Всё приложение (сайт + сервер) собирается из `Dockerfile` в один сервис. Настройки — в `render.yaml`.

## 1. Аккаунт

1. Зайди на https://render.com и нажми **Get Started** → войди через **GitHub** (аккаунт `nagayevarsen`).
2. Разреши Render доступ к репозиторию `olymp-trainer` (можно только к нему).

## 2. Создать сервис из Blueprint

1. В панели Render: **New** → **Blueprint**.
2. Выбери репозиторий `nagayevarsen/olymp-trainer`. Render сам найдёт `render.yaml`.
3. Он попросит значения трёх ключей (в git их нет — вставь из `backend/.env` на компьютере):
   - `OLYMP_ANTHROPIC_API_KEY` — ключ Claude;
   - `GEMINI_API_KEY`, `OPENROUTER_API_KEY` — для проверки ответов (для работы сайта не обязательны).
4. Нажми **Apply**. Первая сборка идёт 5–10 минут.

## 3. Тариф и база данных

В `render.yaml` стоит **бесплатный** тариф. Что нужно знать:
- База (аккаунты, прогресс, стрики) хранится внутри сервиса и **стирается при каждом обновлении
  (git push) и перезапуске**. Задачи не теряются — они в репозитории.
- После 15 минут без посетителей сайт **засыпает**, первый вход потом занимает около минуты
  (и это тоже перезапуск — база стирается).
- Чтобы сайт не засыпал, его каждые 5 минут открывает GitHub (`.github/workflows/keepalive.yml`,
  расписание GitHub примерное) и дополнительно UptimeRobot (монитор HTTP(s) на `https://<ссылка>/api/health`,
  интервал 5 минут). При смене адреса сайта поменять его в обоих местах.
- Перед Demo Day открой сайт за пару минут до выступления и не делай `git push` в день показа.

База лежит на постоянном диске (`disk` в `render.yaml`, `DB_PATH=/var/data/app.db`), тариф `starter`: аккаунты и прогресс не стираются при обновлении. Стоимость — около $7 в месяц плюс диск (цены на render.com/pricing).

## 4. Проверка

1. Когда статус станет **Live**, открой ссылку вида `https://olymp-trainer.onrender.com`.
2. Проверь: `https://<ссылка>/api/health` → `{"ok": true, "problems": …}`.
3. Зарегистрируйся, реши задачу, задай вопрос в чате.

## 5. Обновления

Каждый `git push` в `main` автоматически пересобирает и выкладывает сайт (`autoDeploy: true`).
После выкладки ученикам ничего делать не нужно — новая версия откроется сама.

## Настройки (Environment в панели Render)

| Переменная | Значение | Зачем |
|---|---|---|
| `TRUST_PROXY` | `1` | правильные IP учеников для лимитов |
| `SANDBOX_MAX_PARALLEL` | `2` | запусков кода одновременно (на бесплатном тарифе мало памяти) |
| `AI_GLOBAL_DAILY_LIMIT` | `3000` (по умолчанию) | сколько запросов к ИИ в день на весь сайт |
| `STRONG_PER_USER_DAILY` / `STRONG_GLOBAL_DAILY` | `5` / `150` | лимиты Sonnet в чате |

Все переменные описаны в `backend/.env.example`.
